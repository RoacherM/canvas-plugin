# 🎨 DSH Canvas（@local/dsh-canvas）

这是 DSH 右侧栏里的一块无限画布，用来生产图片、视频等素材。它基于 React Flow，生图用火山方舟 Seedream，生视频用 Seedance，Agent 也能直接读写同一块画布。

## 使用
- **打开画布**：点右侧栏的「＋」，选「Canvas」，然后选一块已有的画布或新建一块。也可以在文件树或对话里点任意 `.dshcanvas` 文件打开。
- **文件位置**：画布保存为 `<工作区>/canvas/<名字>.dshcanvas`，素材放在旁边的 `canvas/assets/`。文件都是普通文件，可以进 git，Agent 也能读写。
- **添加节点**：双击画布空白处弹出「添加节点」菜单（图片、视频、分镜脚本、文字、分组框、生成器、导入素材），节点落在双击的位置；顶部工具栏也有同样的入口。
- **节点即生成器**（0.3，参考 LibTV）：
  - 新建的图片/视频节点是空的，选中后下方展开生成面板：写提示词、选模型和参数，点「生成」或 ⌘↵。
  - 结果直接进入这个节点，成为它的新版本；节点右下角的 ‹ 2/3 › 可以切换版本，旧结果不会丢。
  - 已经有图的图片节点再生成就是「改图」：当前图自动作为第一张参考图（面板里可取消「参考当前图」）。
  - 连线：把图片右侧圆点连到另一个图片节点左侧作为参考图；视频节点左侧有首帧（绿）、尾帧（橙）、参考图（蓝）三个入口。
  - 快捷预设：选中有图的图片节点，顶部工具条有「高清、换角度、打光、九宫格」，点一下会在右边新建一个引用它的节点并立即生成。
- **分镜脚本**：一张镜头表（时长、画面描述、分镜提示词）。每一镜可以单独「生成」分镜图，也可以「生成分镜图 (N)」一次生成所有还没有图的镜头；分镜图排在表格右侧，用紫色虚线和对应的镜头相连。Agent 可以用 `canvas_edit` 的 `add_script` 直接写入分镜。
- **卡片**：
  - 图片、视频：拖入、粘贴或「导入素材」都可以加进来。
  - 文字便签。
  - 分组框：做情绪板、分镜时用。把卡片拖进去就归组，拖出来就解组。
  - 生成节点：分图片、视频两种模式。
- **连线**：把图片右侧的圆点连到生成节点左侧，就成为它的输入。
  - 图片模式只有一个参考图入口。
  - 视频模式有三个入口：首帧（绿）、尾帧（橙）、参考图（蓝）。
- **生成**：点「生成」或按 ⌘/Ctrl+Enter。结果排在节点右侧，每张图都会记下提示词、模型和参考图。再次生成时，新结果排在旧结果下方。
- **卡片工具条**：选中卡片后出现。
  - 图片卡片：以此为参考生图、作为首帧生视频、打开原图。
  - 视频卡片：用尾帧续写视频，也就是用上一段的最后一帧作为下一段的首帧。
- **附加到对话**：选中卡片后点这个按钮，输入框上方会出现一个附件标签。下一条消息发出时，这些卡片会作为一条**独立的**上下文消息（`<canvas_context>` 标签包裹，附带选中的图片）一起发给 Agent，不会写进你输入的文字；点标签上的 × 可以取消。
- **设置**：填写火山方舟 API Key。Key 保存在 DSH 本地凭据库（`ARK_API_KEY`），不会写进画布文件或配置文件。

## 素材库（0.4）
提示词、图片、视频、链接都是带版本的资产，按工作区存放在画布旁边：
```
canvas/library/<id>.json   一个资产一个文件：名称、全部版本（不可修改）、标签（如「定稿」）
canvas/history.jsonl       每次生成一行：时间、画布、节点、提示词版本、参考图版本、模型、产出、耗时、错误
canvas/assets/             媒体文件
```
- **提示词自动建版本**：节点第一次生成时，提示词存成新的提示词资产（名字取节点标签或提示词开头），节点和它绑定。以后改了提示词再生成，就自动存成这个提示词的下一版；改回和旧版一模一样的文字，则直接用回那一版，不重复存。没绑定的节点如果文字和已有的某一版相同，也会直接用那一版。
- **生成面板**上显示绑定的是哪一版，例如「小鸡 · v2」；改动后标黄显示「已修改」。点它打开素材库里的这个提示词，点 × 解除绑定（下次生成就另起一个新提示词）。
- **产物记下来源**：每张生成的图、每段视频都是图片/视频资产的一个版本，`source` 里写着 `p_xxx@2`（用的是哪个提示词的哪一版）、参考图的版本、模型和参数。同一个节点在原地多次生成，结果都算同一个资产的不同版本。导入的文件也会建成资产。
- **素材库抽屉**：点底部工具栏的书本图标打开。
  - 分「全部 / 提示词 / 图片 / 视频 / 链接 / 历史」，可以搜索名称、提示词和标签。
  - 卡片可以拖到画布上：提示词会变成一个绑定该版本的空节点，图片、视频、链接变成对应的卡片。
  - 提示词详情：版本时间线（新的在上），每一版下面是它生成的图；可以写备注「存为新版本」、设为定稿、「用到选中节点」、「放到画布」。
  - 图片/视频详情：每个版本的缩略图和它用的提示词版本（点开跳到那个提示词）。
- **链接**：往画布上粘贴网址，或在「链接」页输入网址，会抓取标题、描述和预览图（预览图下载到 `assets/`），生成一张链接卡片。

## 界面（0.3，参考 LibTV）
- **配色**：深色画布用的是 LibTV 自己的配色（背景 `#141414`、点阵 `#3d3d3d`、节点 `#191e26`、描边 `#363636`），也有浅色版本。默认跟随 DSH 的深浅色，右上角 ☀/☾ 可以固定一种。
- **布局**：
  - 左上角：画布名和保存状态。
  - 右上角：附加到对话、深浅色、设置、全屏。
  - 底部居中：添加节点、选择/移动模式、上传、快捷键。
  - 左下角：小地图、隐藏连线、网格吸附、缩放。
  - 右侧栏较窄时（容器宽度 ≤ 760px），左下角控件改成竖排，工具条只显示图标。
- **节点**：标题和尺寸写在卡片上方；连接点是悬停时出现的圆形「+」，从图片的「+」拖到空白处会弹出菜单，直接新建一个以它为输入的图片或视频节点。
- **截图自查**：`node perf/shots.mjs` 会用无头 Chrome 打开真实画布，把几种状态截图到 `perf/shots/`，并打印布局数据（重叠、超出屏幕的部分、实际生效的颜色）。

## Agent 工具
| 工具 | 作用 |
|---|---|
| `canvas_read` | 读取画布结构（卡片、连线、生成状态），并把你选中的图片交给模型查看 |
| `canvas_edit` | 批量操作：添加图片/视频（给 `prompt` 不给 `path` 就是空的可生成节点）/文字/分组框/分镜脚本（`add_script` + `rows`）/生成节点、更新、删除、连线、网格排列、`run`（开始生成某个节点）。后面的操作可以用 `$N` 引用同一次调用里第 N 个操作新建的卡片 |
| `canvas_generate_image` | 用 Seedream 生图并放到画布上，结果图片会交给模型查看 |
| `canvas_generate_video` | 发起 Seedance 视频任务后立即返回；视频完成后自动出现在画布上 |

工具默认操作你当前打开的那块画布。你在画布上选中的卡片，也就是 `canvas_read` 默认返回的图片。

## 模型
- **图片**：`doubao-seedream-5-0-260128`（默认）、5.0 pro、5.0 flash、4.5。
- **视频**：`doubao-seedance-2-0-fast-260128`（默认）、2.0、2.5、2.0 mini、1.0 pro fast。
- 模型需要先在方舟控制台开通。开通 Seedance 2.x 要求账户余额高于 200 元。
- 接口依据的是火山方舟文档（2026-09-22 版）：图片生成 API（82379/1541523）、创建与查询视频任务（82379/1520757、82379/1521309）。

## 开发
```sh
../pnpm-with-node install
node build.mjs          # 生成 client.js（入口，16KB）和 client.canvas.js（画布，打开时懒加载）
npm test                # 数据模型、Host 路由与工具（模拟方舟）、jsdom 端到端 UI
```

## 安装与回退
```sh
R="/Applications/DeepSeek Harness.app/Contents/Resources/runtime"
cd ~/.dsh/profiles/desktop
DSH_DESKTOP_NODE_EXECUTABLE="/Applications/DeepSeek Harness.app/Contents/MacOS/DeepSeek Harness" \
  "$R/bin/node" "$R/pnpm/bin/pnpm.mjs" add file:/Users/byronwayne/Desktop/DSH/canvas-plugin
```
- **启用**：装好后在「设置 → 插件」里启用 `@local/dsh-canvas`。
- **更新**：每次改完代码先 `node build.mjs`，再执行 `pnpm remove @local/dsh-canvas` 和上面的 `pnpm add`（安装的是一份拷贝）。只重新 `pnpm add` 时，pnpm 会更新已有文件，但**不会复制新增的文件**，插件会因缺文件而加载失败。
- **回退**：在设置里停用，再执行 `pnpm remove @local/dsh-canvas`。

## 设计要点
- **合并规则**：画布文件就是唯一的数据来源，用户和 Agent 可能同时写。每张卡片、每条连线都记录更新时间，删除会留下标记，两边的修改按卡片取较新的一份合并。
- **版本合并**：媒体节点的结果存在 `data.versions`，当前显示哪一个由 `data.shown = { path, at }` 决定，顶层的 `path` 等字段在规范化时从它派生。合并同一个节点时，版本列表按 path 取并集，`shown` 取 `at` 较新的一方。这样浏览器晚到的一次提示词保存（带着旧节点）不会覆盖 Host 刚写入的新版本——这是端到端测试发现的竞态。
- **生成状态独立存放**：生成状态（状态、错误、任务 ID）单独放在 `runs` 里，只由 Host 写。这样用户改提示词时，不会把 Host 刚写入的“已完成”状态覆盖掉。这个问题是端到端测试发现的。
- **Host 写入**：Host 按文件排队读写，并用原子写入，避免浏览器保存、Agent 工具和生成结果互相覆盖。
- **视频任务**：在后台轮询。应用重启后，打开画布会自动续查未完成的任务。结果下载到本地，因为方舟返回的链接 24 小时后失效。
- **打包**：Host 端不导入任何 `@deepseek-ai/*` 包，只使用运行时提供的 `ctx` 服务，因此不会被本机残留的旧版 DSH 包影响。
